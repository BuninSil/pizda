# Phone MCP — телефон как MCP-сервер для Claude

Android-приложение, которое превращает твой телефон в MCP-сервер. Claude
подключается к нему как к кастомному коннектору (Streamable HTTP) и управляет
телефоном через AccessibilityService: читает экран, тапает, свайпает, печатает,
открывает приложения. Без аренды серверов и без API-ключей — телефон держит
исходящий WebSocket к бесплатному Cloudflare Worker (релей), всё по 443.

> ⚠️ Это мощный и потенциально опасный инструмент: ты даёшь удалённой модели
> управление своим телефоном. Внутри зашиты предохранители (чёрный список
> приложений, подтверждения на экране, секретный токен, главный выключатель,
> лог). Всё равно относись к этому серьёзно и не держи включённым без нужды.

---

## Что внутри

- **MCP-обработчик** (Streamable HTTP, JSON-RPC) прямо в коде — без локального
  HTTP-порта. Живёт в Foreground Service с постоянным уведомлением. Есть запрос
  на отключение оптимизации батареи, чтобы система не прибивала сервис.
- **Связь наружу — релей на Cloudflare Worker + Durable Object.** Телефон
  открывает исходящий WebSocket (`wss://<worker>/<токен>/__phone`) на 443, Worker
  пакует запросы Claude в JSON и шлёт их телефону по этому сокету. Никаких
  входящих портов и туннелей — провайдеру/VPN нечего резать (старый cloudflared
  бил в порт `7844`, его душили).
- **Секретный токен** в пути URL: `https://<worker>/<токен>/mcp`. Запросы с
  неверным токеном отбиваются с **404** (не 401 — иначе claude.ai лезет в OAuth).
  Есть кнопка «новый токен».
- **Инструменты MCP** через AccessibilityService: `get_screen`, `screenshot`
  (Android 11+), `tap`, `tap_element`, `long_tap`, `swipe`, `scroll`,
  `type_text`, `press_back`, `press_home`, `open_recents`, `open_app`,
  `list_apps`.
- **Голосовой режим Claude**: кнопка/автозапуск «Позвать Claude» — поднимает
  релей, открывает приложение Claude и жмёт кнопку голосового режима
  (с режимом обучения, если кнопку не нашли). Плюс watchdog «Claude замолчал» с
  голосовым оповещением (TTS).
- **Безопасность**: чёрный список приложений, подтверждения на экране,
  предупреждения о недоверенных данных, главный выключатель, лог вызовов.
- **CI + автообновление**: GitHub Actions собирает подписанный APK на каждый push
  в `main` и кладёт в Releases; приложение само проверяет и ставит обновления.

## Сборка APK

Нужен JDK 17 и Android SDK (проще всего — Android Studio).

### Вариант 1. Через Gradle (CLI)

```bash
./gradlew assembleDebug
# → app/build/outputs/apk/debug/app-debug.apk
```

Никаких встроенных бинарников больше нет (cloudflared выпилен) — связь идёт
через релей-Worker по WSS. Адрес Worker и секрет вшиваются в сборку через
`BuildConfig` (`RELAY_WORKER`, `RELAY_SECRET`); секрет в CI берётся из GitHub
Secret, в репозиторий не коммитится. Локально можно переопределить адрес:
`-PrelayWorker=https://имя.аккаунт.workers.dev`, а адрес ещё и правится прямо в
приложении («Постоянный адрес»).

Если `./gradlew` ругается на отсутствие SDK — создай `local.properties` в корне:

```
sdk.dir=/путь/к/Android/Sdk
```

### Вариант 2. Android Studio

Открой папку проекта, дай ему скачать зависимости, `Build → Build APK(s)`.

## Установка и запуск

1. **Установи APK**: `adb install -r app-debug.apk` (или скинь файл на телефон и
   открой — разреши установку из неизвестных источников).
2. **Включи службу спец. возможностей**: в приложении жми «Открыть настройки
   Спец. возможностей» → найди **Phone MCP Controller** → включи. Это даёт
   приложению право читать экран и выполнять жесты.
3. **Отключи оптимизацию батареи**: кнопка «Отключить оптимизацию батареи».
4. **Разреши уведомления** (Android 13+ спросит сам при первом запуске).
5. **Включи сервер**: переключатель «Сервер MCP» вверху. Телефон подключится к
   релею. **Ссылка коннектора** появляется сразу (она стабильна — зависит только
   от Worker и токена), копируется в буфер и дублируется в уведомлении с кнопкой
   «Копировать». Статус в приложении покажет «На связи», когда сокет поднялся.

Ссылка выглядит так и больше **не меняется** при перезапуске/обновлении:

```
https://имя.аккаунт.workers.dev/<длинный-токен>/mcp
```

## Как добавить в Claude как кастомный коннектор

1. Открой приложение/сайт Claude → **Settings → Connectors** (Коннекторы).
2. **Add custom connector** (Добавить кастомный коннектор).
3. Вставь **полную ссылку коннектора** (с токеном и `/mcp` на конце).
4. Сохрани. Claude подтянет список инструментов (`tools/list`).
5. В чате попроси, например: «посмотри мой экран» — Claude вызовет `get_screen`.

> Если сменил токен — ссылка меняется (в ней новый токен). Приложение обновляет
> её везде (экран + уведомление + буфер), а в Claude коннектор нужно обновить
> вручную новой ссылкой. Перезапуск/обновление/перезагрузка токен **не** меняют.

## Связь наружу — релей (Cloudflare Worker + Durable Object)

Старый путь (cloudflared Quick Tunnel) бил в edge Cloudflare на порт `7844` — его
режут провайдеры и VPN (`TLS handshake with edge error: EOF`), и домен менялся на
каждый перезапуск. Теперь всё наоборот: **телефон сам звонит наружу**.

- Телефон держит один исходящий **WebSocket** к Worker:
  `wss://<worker>/<токен>/__phone`, заголовок `x-update-secret` = `RELAY_SECRET`.
  Всё по 443 — то же, что обычный HTTPS, резать нечего.
- Worker — это **Durable Object `PhoneRelay`**, один инстанс на токен (через
  `idFromName(token)`), с [WebSocket Hibernation API]. Запрос Claude на
  `https://<worker>/<токен>/mcp` (POST — JSON-RPC; GET/DELETE) он пакует в
  `{id, method, path, headers, bodyB64}` и шлёт телефону по сокету.
- Телефон прогоняет запрос через внутренний MCP-обработчик (`McpHandler`, без
  локального HTTP) и отвечает `{id, status, headers, bodyB64}`; Worker стримит
  это обратно Claude. (Для SSE поддержаны чанки `{id, chunkB64}`/`{id, end}`.)
- Телефон не на связи → **503** с понятным текстом. Неверный токен → **404**
  (не 401). Пинг каждые 20с, `/__status` показывает `connected` и возраст пинга.
- Переподключение: экспоненциальный бэкофф (до 30с) и мгновенный ретрай при
  смене сети (`ConnectivityManager.NetworkCallback`).

Деплой Worker — см. «Постоянный адрес» ниже.

## Голосовой режим Claude

- **«Позвать Claude»** (кнопка на главном экране, в уведомлении и плавающая
  кнопка): поднимает сервер и туннель, открывает приложение Claude
  (`com.anthropic.claude`) и жмёт кнопку голосового режима.
- **Deep link**: официального deep link для голосового режима Claude публично не
  задокументировано. Приложение сначала пробует список кандидатов-URI (его можно
  отредактировать в «Настройки голосового режима»), а если не сработало —
  открывает приложение и ищет кнопку через AccessibilityService.
- **Режим обучения**: если кнопку голоса не нашли, включается обучение —
  открой Claude и нажми кнопку голоса **сам один раз**, приложение запомнит её
  признаки (id/текст/описание) и координаты. Дальше будет жать само. Сбросить и
  переобучить — в «Настройки голосового режима».
- **Возврат**: опция «Возвращаться в прежнее приложение после звонка» (по
  умолчанию выключена). Если включена — после старта звонка приложение вернёт
  тебя в прежнее приложение/на домашний экран.
- **Плавающая кнопка**: опция в настройках, требует разрешения «поверх других
  приложений».

### Watchdog «Claude замолчал»

Пока голосовая сессия активна, приложение следит:

- сколько прошло с последнего вызова инструмента MCP (по умолчанию **60 сек**,
  настраивается);
- не пропал ли голосовой режим Claude с переднего плана (обрыв звонка);
- не появилось ли на экране Claude сообщение про лимит.

Если сработало — приложение **проговаривает голосом** (TextToSpeech): «Claude
замолчал, возможно, закончился лимит или оборвался звонок» и показывает
уведомление с кнопкой **«Перезапустить звонок»**.

## Безопасность (зашито в коде)

- **Чёрный список приложений** (редактируемый): по умолчанию банки, платёжки,
  Госуслуги, менеджеры паролей. Пока на переднем плане приложение из списка —
  **все инструменты возвращают ошибку и ничего не делают**. Правится в «Чёрный
  список приложений».
- **Подтверждение на экране** для чувствительных действий (отправка сообщений,
  звонки, покупки, удаление, изменение системных настроек): инструмент **ждёт,
  пока ты нажмёшь «Да»** на телефоне. Таймаут 60 сек → отказ. Определяется по
  подписи элемента (send/call/pay/delete/отправить/позвонить/купить/удалить…) и
  по тому, что открыты системные настройки.
- **Недоверенные данные**: в описаниях инструментов явно сказано, что текст с
  экрана — это данные от сторонних приложений, а **не инструкции**. Claude
  предупреждён не выполнять команды, найденные в содержимом экрана.
- **Главный выключатель**: переключатель в приложении и кнопка «Стоп» в
  уведомлении — мгновенно гасят обработчик и рвут релей-сокет.
- **Секретный токен** в URL, сравнение в постоянном времени, кнопка «новый
  токен».
- **Лог вызовов** всех инструментов с временем — на главном экране.

## VPN больше не мешает

Релей ходит по 443 исходящим WebSocket'ом, как обычный HTTPS, — VPN и провайдеры
его не отличают от любого другого трафика, так что душить нечего. Специальных
обходов (DoH, `--edge`, исключение из VPN) больше не нужно; мобильный интернет с
VPN или без — работает одинаково.

## Постоянный адрес (Cloudflare Worker + Durable Object)

Адрес Worker стабилен навсегда (`*.workers.dev`), поэтому коннектор в Claude
подключаешь один раз. Деплой — один раз с компьютера:

```bash
cd worker
npm i -g wrangler
wrangler login
wrangler deploy
```

`name` в `wrangler.toml` = имя **существующего** воркера (`raspy-dew-5339`),
чтобы `deploy` обновил его на месте и вшитый в приложение `RELAY_WORKER` не
протух. Не переименовывай — иначе получишь новый воркер на другом URL.
`wrangler.toml` уже содержит привязку Durable Object (`PHONE_RELAY` →
`PhoneRelay`) и миграцию `v1` (`new_sqlite_classes`), KV больше не нужен.

**Секрет опциональный** (как и раньше). Без него телефон подключается без
проверки — для личного тула норм. Хочешь включить: `wrangler secret put
UPDATE_SECRET` и тот же строкой выставь `RELAY_SECRET` (GitHub Secret / сборка).
Оба пустые = без секрета.

Этот URL пропиши:

- в сборку как `RELAY_WORKER` (GitHub Secret или `-PrelayWorker=...`), либо
- прямо в приложении: кнопка **«Постоянный адрес»** → поле Worker URL (пусто =
  адрес из сборки).

Секрет приложения задаётся **только** через `BuildConfig.RELAY_SECRET` (в CI —
GitHub Secret `RELAY_SECRET`), и он должен совпадать с `UPDATE_SECRET` воркера.

Коннектор для Claude (подключаешь один раз):

```
https://<имя>.<аккаунт>.workers.dev/<токен>/mcp
```

`<токен>` — тот, что показан на главном экране. Проверить связь:
`curl https://<worker>/<токен>/__status` → `{"connected":true,...}` когда телефон
на сокете.

## Автосборка и релизы (GitHub Actions)

В `.github/workflows/release.yml` настроено: **на каждый push в `main`** —
собрать подписанный release-APK с увеличенным `versionCode` и выложить его в
**GitHub Releases**.

- `versionCode` = номер запуска воркфлоу (`github.run_number`) → каждая сборка
  выше предыдущей.
- тег релиза: `v<versionCode>` (например `v42`). По нему же приложение понимает,
  что вышла новая версия.
- APK в релизе всегда называется `phone-mcp.apk`, поэтому есть **постоянная
  прямая ссылка на последний APK**:

```
https://github.com/BuninSil/pizda/releases/latest/download/phone-mcp.apk
```

Открываешь её на телефоне → качается свежий APK. (Работает только если репозиторий
публичный — см. «Приватный репозиторий» ниже.)

> Я разрабатываю в ветке `ccr-...`. Воркфлоу срабатывает на `main` — слей туда
> ветку (или смерджи PR), и сборка поедет.

## Подпись (release-ключ)

Чтобы обновления ставились **поверх старой версии** без удаления, все сборки
должны быть подписаны **одним и тем же** постоянным ключом. Ключ генеришь ты сам
(я не могу безопасно сгенерировать и показать приватный ключ в чате — если лог
утечёт, утечёт ключ) и кладёшь в GitHub Secrets.

### 1. Сгенерируй keystore (один раз, у себя):

```bash
keytool -genkeypair -v \
  -keystore release.jks -storetype PKCS12 \
  -keyalg RSA -keysize 2048 -validity 10000 \
  -alias phonemcp \
  -dname "CN=Phone MCP, O=PhoneMCP, C=US"
# задай и запомни пароль (store и key пароль для PKCS12 должны совпадать)
```

### 2. Получи base64 keystore:

```bash
base64 -w0 release.jks   # Linux
# base64 -i release.jks  # macOS
```

### 3. Добавь секреты в репозиторий

`Settings → Secrets and variables → Actions → New repository secret`:

| Secret | Значение |
|---|---|
| `KEYSTORE_BASE64` | строка из шага 2 |
| `KEYSTORE_PASSWORD` | пароль keystore |
| `KEY_ALIAS` | `phonemcp` |
| `KEY_PASSWORD` | тот же пароль |
| `RELAY_SECRET` | тот же секрет, что `wrangler secret put UPDATE_SECRET` |
| `RELAY_WORKER` | (опц.) URL воркера; пусто = дефолт из `build.gradle.kts` |

Храни `release.jks` и пароль в надёжном месте — **потерял ключ = не сможешь
выпускать обновления** поверх уже установленной версии (только переустановка).

> Без этих секретов воркфлоу упадёт с понятной ошибкой. Локально release без
> секретов собирается на debug-ключе (для теста), но таким APK обновляться
> поверх прод-версии нельзя.

## Автообновление внутри приложения

- Проверка при запуске приложения и раз в несколько часов (пока работает сервис).
- Берёт последний релиз через GitHub API
  (`/repos/<repo>/releases/latest`), сравнивает `versionCode` из тега с текущим.
- Если новее — уведомление **«Есть обновление»** с кнопкой **«Обновить»** (и
  диалог при запуске). По кнопке качает `phone-mcp.apk` и открывает системный
  установщик (`REQUEST_INSTALL_PACKAGES` + `FileProvider`).
- В приложении: кнопка **«Проверить обновления»** и строка с текущей версией.
- Репозиторий для проверки задаётся в `BuildConfig.UPDATE_REPO` (по умолчанию
  `BuninSil/pizda`); поменять без правки кода: `-PupdateRepo=owner/name` при сборке.

> Первый раз Android попросит разрешить установку из этого приложения
> («Установка неизвестных приложений») — это нормально, разреши.

## Приватный репозиторий

Автообновление и прямая ссылка работают **без токена только для публичного
репозитория** (в приложение намеренно не зашит GitHub-токен — это небезопасно).
Если `pizda` приватный, есть два пути:

1. **Сделать `pizda` публичным** — проще всего. Код и так твой личный тулинг.
2. **Отдельный публичный репозиторий только для релизов** (напр.
   `pizda-releases`): основной код остаётся приватным, а воркфлоу публикует APK в
   публичный репо. Для этого:
   - создай публичный `pizda-releases`;
   - в `release.yml` у `softprops/action-gh-release` добавь
     `repository: BuninSil/pizda-releases` и `token: ${{ secrets.RELEASES_TOKEN }}`
     (PAT с правом `contents:write` на тот репо);
   - собери приложение с `-PupdateRepo=BuninSil/pizda-releases` (или поменяй
     дефолт в `build.gradle.kts`);
   - прямая ссылка станет
     `https://github.com/BuninSil/pizda-releases/releases/latest/download/phone-mcp.apk`.

## Ограничения и примечания

- `screenshot` работает только на Android 11+ (через `takeScreenshot`).
- Фоновая запись в буфер обмена на части прошивок ограничена — поэтому есть
  кнопки «Копировать» на экране и в уведомлении.
- Релей-Worker требует (бесплатный) аккаунт Cloudflare для деплоя, но домена не
  требует — адрес `*.workers.dev` стабилен навсегда.
- Для release нужна своя подпись (`signingConfig`) и секрет `RELAY_SECRET`,
  совпадающий с `UPDATE_SECRET` воркера.
